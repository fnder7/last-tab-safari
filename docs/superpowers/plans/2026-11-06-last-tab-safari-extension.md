# Last Tab Safari Extension Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a macOS Safari Web Extension whose keyboard command toggles between the two most recently active tabs of the focused window.

**Architecture:** The web extension lives in `extension/` as plain ES modules. `mru.js` holds the pure state logic. `controller.js` wires browser events to it through an injected `browser` object, so it can be tested with a fake. `background.js` is a one-line entry point. The Xcode container app is generated once by `safari-web-extension-converter`, and it references `extension/` in place.

**Tech Stack:** Manifest V3 Safari Web Extension; JavaScript ES modules; Node 20 `node --test` (no npm dependencies); Xcode 26.6 / AppKit container generated by `xcrun safari-web-extension-converter`.

**Spec:** `docs/superpowers/specs/2026-11-06-last-tab-safari-extension-design.md`

## Global Constraints

- macOS only, Safari 26+. No iOS target (`--macos-only`).
- Manifest permissions are exactly `["tabs", "storage"]`. No `host_permissions`, no `content_scripts`.
- A single command named `toggle-last-tab`.
- State lives only in `browser.storage.session` under the key `mruState`.
- No npm dependencies. Tests run with `node --test tests/`.
- App name is `Last Tab`. The bundle identifier is `dev.fnder77.LastTab`, and the extension's is `dev.fnder77.LastTab.Extension` (the converter's default suffix). Confirm these with the user before Task 1 Step 3.
- Out of scope: deeper history, a picker overlay, toolbar button/popup/options page, iOS, persistence across Safari restarts.

## Review Focus

1. **Rapid repeated presses.** Two commands can arrive before the first `onActivated` lands. Expected: every event is processed in order through one promise chain, and nothing is lost or double-applied. Tested in Task 3 (`serializes events`).
2. **Background unloaded between events.** Expected: state is reloaded from `storage.session`, and the toggle still works after a fresh `createController`. Tested in Task 3 (`restores state from storage`).
3. **A tab dragged to another window** (`tabs.onDetached`). Expected: it is forgotten in the old window, so the shortcut never activates a tab in a different window. Tested in Task 2 (`onTabRemoved` is reused) and Task 3 (`detached tab is forgotten`).
4. **The target tab vanished** (`tabs.update` rejects). Expected: no uncaught error, `previous` is cleared, and the next press is a no-op. Tested in Task 3 (`clears previous when update rejects`).
5. **No focused window or no entry yet** (the Safari launch restored windows without `onActivated`). Expected: the command is a silent no-op, and the focused window gets seeded at startup. Tested in Task 3 (`seeds focused window at startup`, `command without entry is a no-op`).

### Task 2: Pure MRU state module

**Files:**
- Create: `extension/mru.js`
- Test: `tests/mru.test.js`

**Interfaces:**
- Produces (all named exports; state is a plain object keyed by window id as a string; functions never mutate their input and return a new object):
  - `emptyState(): State` returns `{}`
  - `onActivated(state: State, windowId: number, tabId: number): State`
  - `onTabRemoved(state: State, windowId: number, tabId: number): State`
  - `onWindowRemoved(state: State, windowId: number): State`
  - `targetFor(state: State, windowId: number): number | null`
  - `State = { [windowId: string]: { current: number | null, previous: number | null } }`

- [ ] **Step 1: Write the failing tests** in `tests/mru.test.js` (import from `../extension/mru.js`):

```js
test('toggle: A then B targets A; activating A targets B', () => {
  let s = onActivated(onActivated(emptyState(), 1, 10), 1, 20);
  assert.equal(targetFor(s, 1), 10);
  s = onActivated(s, 1, 10);
  assert.equal(targetFor(s, 1), 20);
});
test('first tab has no target', () => {
  assert.equal(targetFor(onActivated(emptyState(), 1, 10), 1), null);
  assert.equal(targetFor(emptyState(), 1), null);
});
test('re-activating current keeps previous', () => {
  const s = onActivated(onActivated(onActivated(emptyState(), 1, 10), 1, 20), 1, 20);
  assert.equal(targetFor(s, 1), 10);
});
test('closing previous clears target', () => {
  const s = onTabRemoved(onActivated(onActivated(emptyState(), 1, 10), 1, 20), 1, 10);
  assert.equal(targetFor(s, 1), null);
});
test('closing current keeps previous for next activation', () => {
  // tabs A=10, B=20, C=30; on C with previous B; close C, Safari activates A
  let s = [10, 20, 30].reduce((st, t) => onActivated(st, 1, t), emptyState());
  s = onActivated(onTabRemoved(s, 1, 30), 1, 10);
  assert.equal(targetFor(s, 1), 20);
});
test('closing current then activating previous clears previous', () => {
  let s = onActivated(onActivated(emptyState(), 1, 10), 1, 20);
  s = onActivated(onTabRemoved(s, 1, 20), 1, 10);
  assert.equal(targetFor(s, 1), null);
});
test('windows are independent', () => {
  let s = onActivated(onActivated(emptyState(), 1, 10), 1, 20);
  s = onActivated(onActivated(s, 2, 30), 2, 40);
  assert.equal(targetFor(s, 1), 10);
  assert.equal(targetFor(s, 2), 30);
});
test('removing a window deletes its entry', () => {
  const s = onWindowRemoved(onActivated(onActivated(emptyState(), 1, 10), 1, 20), 1);
  assert.deepEqual(s, {});
});
test('functions do not mutate input', () => {
  const s = Object.freeze(onActivated(emptyState(), 1, 10));
  Object.freeze(s['1']);
  assert.doesNotThrow(() => { onActivated(s, 1, 20); onTabRemoved(s, 1, 10); onWindowRemoved(s, 1); });
});
```

Freezing makes mutation throw, because ES modules run in strict mode.

### Task 3: Controller and background wiring

**Files:**
- Create: `extension/controller.js`
- Modify: `extension/background.js` (replace the spike)
- Test: `tests/controller.test.js`, `tests/fake-browser.js`

**Interfaces:**
- Consumes: everything from `mru.js` (Task 2).
- Produces: `createController(browser): { ready: Promise<void>, idle(): Promise<void> }` (named export).
  - It registers listeners **synchronously** on `browser.tabs.onActivated`, `browser.tabs.onRemoved`, `browser.tabs.onDetached`, `browser.windows.onRemoved` and `browser.commands.onCommand` before any `await`.
  - `ready` resolves after the state has loaded from `storage.session` (`mruState`) and the focused window (`browser.windows.getLastFocused()`) has been seeded via `onActivated` with its active tab, if there is no entry for it yet.
  - `idle()` resolves when the internal event chain is empty (tests use it).
- `background.js` becomes: `import { createController } from './controller.js'; createController(browser);`
- `tests/fake-browser.js` exports `createFakeBrowser({ tabs: [{id, windowId, active}], focusedWindowId, sessionData = {} })`. It returns `{ browser, fire(eventPath, ...args), updateCalls, session }`. Each `on*` is `{ addListener(fn) }`. `fire('tabs.onActivated', {tabId, windowId})` calls the listeners. `tabs.update(id, {active})` records the call into `updateCalls` and rejects if `id` isn't in `tabs`. It does **not** auto-fire `onActivated`; tests fire it explicitly. `storage.session.get/set` read and write the `session` object. `windows.getLastFocused()` resolves `{id: focusedWindowId}`. `tabs.query({active: true, windowId})` returns the matching tabs from `tabs`.

**Event-chain algorithm (not determined by the tests alone):**

```js
let state = emptyState();
let chain = load();               // load(): read mruState, seed focused window, assign state
const ready = chain;
const enqueue = (fn) => (chain = chain.then(fn).catch(e => console.error('[LastTab]', e)));
// each listener: (...args) => enqueue(async () => { state = mru.X(state, ...); await save(); })
```

The command handler gets `windowId` from `browser.windows.getLastFocused()`. If `targetFor` is null, it returns. Otherwise it calls `await browser.tabs.update(target, { active: true })`. If that rejects, it applies `onTabRemoved(state, windowId, target)` and saves. `onRemoved` with `removeInfo.isWindowClosing` → `onWindowRemoved`. `onDetached(tabId, {oldWindowId})` → `onTabRemoved(state, oldWindowId, tabId)`.

  - `second press goes back`: continuing that setup, fire the `onActivated` for 10 (the effect of the update), then the command again. The last update call is to `20`.
  - `command without entry is a no-op`: sessionData `{}`, focused window 2 with no tabs. After the command, `updateCalls` is `[]`.

  - `restores state from storage`: sessionData `{mruState: {'1': {current: 20, previous: 10}}}`. The command → update to `10`.
  - `persists state`: after one activation, `session.mruState['1'].current` equals the activated tab.
  - `clears previous when update rejects`: state targets tab 99 (not in `tabs`). The command does not throw; `session.mruState['1'].previous === null`.
  - `detached tab is forgotten`: window 1 has current 20 and previous 10. Fire `tabs.onDetached(10, {oldWindowId: 1})`. The command → `updateCalls` is `[]`.
